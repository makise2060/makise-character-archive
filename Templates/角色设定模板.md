## 十一、图片素材（可选但推荐）

- 角色设定**鼓励携带图片**（立绘、官方图、同人参考、关系图等），便于直观呈现与扮演。
- 图片统一存放在设定文档**同级**的 `images/` 目录，使用**相对路径**引用，便于管理与跨设备整理：
  `![描述](images/character-portrait.png)`
- 命名建议：`<角色>-<用途>.<ext>`（如 `shorekeeper-portrait.png`、`shorekeeper-ost-icon.webp`）。
- 多角色同游戏时：可在游戏目录下统一 `images/` 并按角色前缀区分；也可为每个角色单独建 `images/`。
- 图片随文档一起纳入版本管理（Git / GitHub），确保相对路径在仓库中始终有效。

### 设定图片查找方式（无需每次从头试能力）

以 **Fandom Wiki** 为例（多数二次元游戏角色 Wiki 通用此结构）：

1. **URL 规律**：`<游戏英文名> Wiki` → `https://<game>.fandom.com/wiki/<角色名>`；立绘 / 卡面 / 资料表等游戏资产通常在 **`/Gallery` 子页**（如 `.../Shorekeeper/Gallery`）。
2. **用 MediaWiki API 列文件（最稳，直接出直链）**：
   `https://<game>.fandom.com/api.php?action=query&format=json&list=allimages&aiprefix=<角色名>&ailimit=300`
   返回 JSON 中每项含 `name` 与 `url`（直链），按文件名挑 Splash Art / Card / Character Sheet / Convene Still / Idle / 意象图等。
3. **缺直链时**：用 WebFetch 抓取 `/Gallery` 页，提取 `File:` 页地址与 `static.wikia.nocookie.net` 直链；Fandom 主页面通常只有 UI 图标，立绘在 Gallery 子页。
4. **其他图源**：官方网站「角色」页、游戏内「图鉴 / 档案」截图、官方 PV 静帧；同人参考图需注明画师与出处。
5. **下载与引用**：
   - 下载到设定文档同级的 `images/`，按 `<角色>-<用途>.<ext>` 命名（如 `shorekeeper-splash-art.png`）。
   - 文档内以相对路径引用：`![描述](images/shorekeeper-splash-art.png)`。
   - **务必标注版权归属**（如 Kuro Games）与来源（Wiki / Fandom）。
6. **提交**：`git add` → `commit` → `git push origin main`。
7. **坚果云避坑**：若仓库在坚果云同步目录下，直接写入的图片可能被流式同步的「空状态」回滚删除。对策——先下载到非同步临时目录（如 `D:/sk_images_tmp/`），再用 `git hash-object -w <文件>` 取 blob、`git update-index --add --cacheinfo 100644 <sha> <路径>` 直接写入索引，最后 `commit` 推送，可绕开工作区副本被删的问题。
